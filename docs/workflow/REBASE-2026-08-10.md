# Workflow Rebase — 10 August 2026

## Baseline

The package was rebased from the Phase 19 Scout Report release artifact. The existing PostgreSQL reference-data CRUD, authentication/session model, report storage, dashboards, metrics, CI/release documentation and regression tests are retained.

## Functional change

The authorization model is extended from:

`admin` / `scout`

to:

`admin` / `scout` / `inter_farm_supervisor` / `head_of_department`

The application no longer treats an unknown elevated role as a scout dashboard user.

## New data model

- `report_workflows`
- `report_workflow_events`

## New UI

- `/inter-farm-supervisor-dashboard`
- `/head-of-department-dashboard`
- `/admin-verification-dashboard`
- workflow controls on the scout dashboard

## New API

- `/api/workflow/inbox`
- `/api/workflow/:id`
- `/api/workflow/recipients/:role`
- `/api/workflow/:id/share`
- `/api/workflow/:id/verify`

## Verification philosophy

Organizational workflow state is separate from agronomic report severity. The existing `Pending`, `Completed` and `Critical` status values remain available for report health/severity and are not repurposed for approval state.

## Rollback

Before migration, take a PostgreSQL backup. To roll back application code, restore the previous release artifact. Do not drop workflow tables in production until the organization confirms that workflow audit history is no longer required.
