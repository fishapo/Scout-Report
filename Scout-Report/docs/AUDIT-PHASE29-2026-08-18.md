## Executive conclusion

The project is **not clean enough to resume feature development blindly**. The application source is syntactically valid, the dependency lock is internally installable, and most automated tests pass, but the uploaded baseline contains:

1. a large `node_modules` directory that should never be transported as project source;
2. a real `.env` and `.env.BAD-BACKUP` that must stay outside Git;
3. a nested stale/duplicate `Scout-Report-Reviewed-2026-08-14` project snapshot;
4. several `.bak` files;
5. a stale phase roadmap that does not match the actual Phase 24–28 implementation history;
6. a **monolithic `server/auth.js`** in the uploaded tree — the modular auth files discussed earlier are **not present in this ZIP**;
7. **8 failing tests** out of 129 in the current environment, mostly caused by test mocks not matching the current SQL contract;
8. no `.env.example` at the root, despite documentation referring to one;
9. no `.github/workflows/azure-webapps-node.yml` in the uploaded root, despite README claims that it exists.

This means the next development cycle should begin with a **baseline cleanup + test-contract repair + architecture reconciliation**, not with another feature phase.

## Current 8 failures

- **farm delete blocks farms referenced by scout reports** — Test mock does not handle: SELECT COUNT(*)::int AS count FROM scout_reports sr WHERE farm_id = $1
- **farm delete removes an unused farm and reports missing farms** — Same farm-delete test mock SQL coverage gap
- **Docker PostgreSQL initialization runs the complete migration directory** — Migration/docker verification failure; inspect the exact verifier output before changing migration order
- **saveReport creates a report and observations transactionally** — Test mock does not handle findReport SELECT after save
- **findReport returns null for missing reports** — Test mock does not handle current findReport SELECT
- **updateReport validates fields and returns the updated report** — Test mock does not handle current findReport SELECT
- **addPestObservation returns null for missing reports and refreshes status when found** — Test mock does not handle current findReport SELECT
- **deleteReport removes existing reports and reports misses** — Test mock does not handle current findReport SELECT

### Interpretation

The dominant failures are **test fixture/mock contract drift**, not JavaScript syntax errors. The current `server/store.js` performs a `findReport()` refresh/read in several CRUD paths, while older test mocks do not recognize that SELECT. Do not weaken production code to satisfy the mock. Update the test mock to model the current SQL contract, then rerun the affected tests.

The farm-delete failures are the same class of issue: the production store checks whether reports reference the farm, while the test mock lacks the corresponding count query.

The Docker migration failure must be isolated separately with its verifier output before changing migration files.

## Definition of a clean baseline

A clean baseline is not "npm test passes once." It requires:

- clean Git status except intentional changes;
- no tracked secrets;
- no node_modules in Git;
- no nested project snapshot;
- deterministic `npm ci`;
- all JS syntax valid;
- all tests passing or explicitly quarantined with a documented reason;
- migration sequence verified;
- `.env.example` complete;
- API route inventory matches implementation;
- browser routes match the current auth contract;
- reference IDs/names match the live database;
- phase documentation points to one current next step.
